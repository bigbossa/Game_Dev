# เพิ่มความลื่นบนคอมและมือถือ — 26 ตุลาคม 2026

ปรับ renderer ต่อจาก [การลดงานวาดซ้ำรอบก่อน](render-performance.md) และเพิ่ม **ตั้งค่า → คุณภาพกราฟิก** ซึ่งจำค่าต่อเบราว์เซอร์:

- **อัตโนมัติ** (ค่าเริ่มต้น): ลดความละเอียดภาพฉากทีละขั้นเมื่อเฟรมช้าต่อเนื่อง และคืนความละเอียดเมื่อเครื่องทำงานได้เร็วต่อเนื่อง เมื่อภาระสูงจะลดออร่าตกแต่งและแสงเรืองของฉากด้วย
- **สวยเต็มที่**: คงออร่าและความละเอียดระดับสูง ไม่ปรับตาม FPS
- **เน้นลื่น**: ลดความละเอียดฉาก ออร่าตกแต่ง และจำนวนประกายทันที เหมาะกับเครื่องที่กระตุกมาก

ตัวหนังสือและปุ่ม HTML ยังใช้ความละเอียดหน้าจอเดิม ตัวละคร มอนสเตอร์ เป้าหมาย จังหวะสกิล และวงเตือนยังทำงาน ความละเอียด Canvas ไม่เปลี่ยนพิกัดการคลิก การเดิน ความเร็วต่อสู้ หรือเวลาเครือข่าย

## งานที่ลดลง

- ปรับเฉพาะ Canvas ของฉาก ไม่ลดความละเอียด HUD; ใช้พื้นหลังทึบเพราะวาดฉากเต็มพื้นที่อยู่แล้ว
- จำกัดอนุภาคตกแต่งไว้ที่ 700 / 1,800 / 300 ชิ้นสำหรับอัตโนมัติ / สวยเต็มที่ / เน้นลื่น ตามลำดับ ทั้งตัวปล่อยทั่วไปและตัวที่เพิ่มอนุภาคตรง ๆ และไม่สร้างประกายจากจุดที่อยู่ไกลนอกจอ
- แคชภาพตัวเลขดาเมจตามข้อความ สี ขนาด และ DPI สูงสุด 256 รายการ รวมไม่เกิน 2 ล้านพิกเซล (ประมาณ 8 MB ของข้อมูล RGBA) ล้างแคชเมื่อฟอนต์โหลดเสร็จ
- ลดการบันทึกและคืนสถานะ Canvas ซ้ำตอนวาดของตกแต่งและมอนสเตอร์ในสถานะปกติ โดยคงเส้นทางเดิมสำหรับการกลับด้าน กระพริบเมื่อถูกโจมตี และความโปร่งใส
- มินิแมปอัปเดตไม่เกิน 10 ครั้ง/วินาทีและทันทีเมื่อเปลี่ยนแผนที่; HUD อัปเดตเมื่อได้รับสถานะชุดใหม่ทันที และอัปเดตคูลดาวน์ระหว่างแพ็กเก็ตไม่เกิน 20 ครั้ง/วินาที
- หยุดเขียนสถานะซ่อนแถบคอมโบนักมวยซ้ำทุกเฟรมเมื่อเล่นอาชีพอื่น

โหมดอัตโนมัติใช้ค่าเฉลี่ย 120 เฟรม ลดระดับเมื่อค่าเฉลี่ยเกิน 22 ms และเว้นช่วงหลังเปลี่ยนระดับเพื่อไม่ให้ปรับถี่เกินไป คืนระดับเมื่อค่าเฉลี่ยต่ำกว่า 17.5 ms ต่อเนื่อง 8 ช่วง ไม่ใช้เวลาที่แท็บถูกซ่อนหรือกำลังโหลดแผนที่ตัดสินลดคุณภาพ

## ผลทดสอบ

ใช้ renderer จริงใน Edge บนเครื่องพัฒนาเดียวกัน ฉากละ 7 วินาที ตัดช่วงอุ่นแคช 2 วินาที เรียงฉากเดิน → มอนสเตอร์ 48 ตัว → เอฟเฟกต์หนัก โหมดหลังปรับคืออัตโนมัติและคงสถานะการปรับคุณภาพข้ามฉาก จึงยังมีช่วงเรียนรู้ภาระในสองฉากแรก

| รูปแบบจอ / ฉาก | ก่อน (FPS) | หลัง (FPS) |
| --- | ---: | ---: |
| คอม 1280×900 DPR 1 — เดิน | 44.8 | 47.4 |
| คอม — มอนสเตอร์ 48 ตัว | 38.4 | 59.6 |
| คอม — เอฟเฟกต์หนัก | 32.1 | 55.6 |
| มือถือจำลอง 390×844 DPR 3 — เดิน | 46.0 | 49.8 |
| มือถือจำลอง — มอนสเตอร์ 48 ตัว | 40.6 | 42.0 |
| มือถือจำลอง — เอฟเฟกต์หนัก | 37.4 | 59.6 |

เวลาเฟรม P95 ของฉากเอฟเฟกต์หนักลดจาก 50.0 เป็น 33.3 ms บนจอคอม และ 33.4 เป็น 16.8 ms บนจอมือถือจำลอง เมื่อจบฉาก โหมดอัตโนมัติลดสเกลฉากเหลือ 80% และปิดออร่าตกแต่ง จึงเป็นผลร่วมของการลดงานซ้ำและการลดคุณภาพบางส่วน ไม่ใช่การเทียบภาพที่เหมือนกันทุกพิกเซล

ฉากเอฟเฟกต์หนักปล่อยอนุภาค 1,200 ชิ้นทุก 250 ms จาก 12 จุด โดย 10 จุดอยู่นอกจอ เป็น stress test สังเคราะห์ ผลมือถือมาจากการจำลองขนาดจอ/DPR/ระบบสัมผัสบนคอม ไม่ใช่ฮาร์ดแวร์โทรศัพท์จริง และไม่ได้วัดความหน่วงเครือข่าย ผล FPS ขึ้นกับเครื่องและฉากที่เล่น

ข้อมูล: `artifacts/performance/smooth-before.json`, `smooth-after.json`, `smooth-mobile-before.json`, `smooth-mobile-after.json` (โฟลเดอร์ artifacts ไม่เข้า Git) การวัด HUD ในสคริปต์เรียก `HUD.update` ทุกเฟรมโดยตรงเพื่อเทียบงานภายใน ไม่ใช่การวัดผลของตัวจำกัดการอัปเดต HUD ในลูปเกม

## ตรวจซ้ำ

```powershell
node tools/check-render-quality.cjs
node tools/check-character-motion.cjs
node tools/preview-village.cjs 3922
# อีก terminal: เปิด Edge/Chromium สำหรับทดสอบที่พอร์ต CDP 9362
node tools/benchmark-render.cjs desktop http://127.0.0.1:3922 9362 --verify
node tools/benchmark-render.cjs mobile http://127.0.0.1:3922 9362 --mobile --verify
```

รัน benchmark ทีละตัวเพื่อไม่ให้แย่งทรัพยากร ตัวเลือก `--baseline-smooth` ใช้สำเนาก่อนแก้ใน `artifacts/smooth-v2/baseline/public/js` ผ่าน CDP interception ไม่เขียนทับ source และไม่ล็อกอินหรือบันทึกบัญชีผู้เล่น

ชุดตรวจครอบคลุมสถานะ HUD คูลดาวน์ แคชชื่อ/ดาเมจและการโหลดฟอนต์ เปรียบเทียบพิกเซลการตัดประกายนอกจอ การหมดอายุ callback สกิล การจำกัดจำนวนอนุภาค การเปลี่ยน/จำค่ากราฟิก ขนาดช่องเลือกบนมือถือ และพิกัดการคลิกที่ต้องตรงกันเมื่อเปลี่ยนความละเอียด ส่วน unit checks ตรวจการลด/คืนคุณภาพ การซ่อนแท็บ โหมดคงที่ เพดานพิกเซล และการเคลื่อนไหวที่ไม่ขึ้นกับ refresh rate

## เกมที่เปิดอยู่

นำ frontend 9 ไฟล์เข้าเกม `http://127.0.0.1:3900` ด้วยอิมเมจ `yhg-game:smooth-20261026` ที่ต่อจากเวอร์ชันนักมวย ใช้ three-way merge เก็บความต่างเดิมของไฟล์ในเกมกับ workspace และตรวจ SHA-256 ของไฟล์ที่เสิร์ฟครบ 9 ไฟล์ (`artifacts/smooth-v2/deployed.json`) อิมเมจและข้อมูลผู้เล่นเดิมยังอยู่ ผู้เล่นรีโหลดหน้าเพื่อรับแพตช์

ตรวจ renderer ที่เสิร์ฟจากเกมหลังอัปเดตผ่าน 28 กรณี (`artifacts/performance/smooth-live.json`) ได้ FPS เดิน / มอนสเตอร์ / เอฟเฟกต์หนัก 51.6 / 37.8 / 56.2 ผลฉากมอนสเตอร์ในช่วงแรกผันผวนตามเวลาที่ตัวปรับอัตโนมัติเริ่มลดคุณภาพ จึงไม่รับรองว่าแต่ละฉากหรือแต่ละเครื่องจะได้ FPS เท่ากับตารางเสมอไป
